# 从一组素材到分发与复盘

这个示例用“把收藏的链接变成每周可用的阅读清单”串起六个 Skill。先看完整稿，再沿编号回看输入与判断，也可以按下表顺序逐步运行。

**所有角色、访谈、操作记录、日期、发布指标和读者反馈均为合成演示材料。** 文件是人为编写的预期交付示例，不是模型实测报告，不代表真实作者经历、真实用户研究或效果提升。文件中的“已证实”只表示在指定的演示材料范围内一致，不构成现实事实核验。真实发布前应替换为自己的可追溯材料。

| 顺序 | 文件 | 可以检查什么 |
| --- | --- | --- |
| 0 | [演示输入与来源编号](reading-workflow/source-notes.md) | 材料到底说了什么，哪些没有说 |
| 1 | [选题评估](reading-workflow/01-topic.md) | 评分方向、作者资格缺口、是否值得写 |
| 2 | [标题候选](reading-workflow/02-titles.md) | 12 个候选、评分门槛与淘汰理由 |
| 3 | [文章地图与大纲](reading-workflow/03-structure.md) | 事实、案例、判断、待核材料如何分开 |
| 4 | [完整短成稿](reading-workflow/04-article.md) | 标题承诺能否被正文兑现 |
| 5 | [核查台账](reading-workflow/05-fact-check.md) | 被证伪的说法如何纠正，来源冲突如何保留 |
| 6 | [知乎与头条分发草稿](reading-workflow/06-distribution.md) | 两个平台的结构变化与事实边界 |
| 7 | [固定 24 小时窗口复盘](reading-workflow/07-review.md) | 缺失值、分母与下一轮假设 |

文件顺序是阅读顺序。实际创作中，先形成正文，再核验标题准确性；核查后也可能回到选题和大纲。本例的标题评分已对照第 4 份最终正文完成。

建议试用方式：给 Agent 提供 `source-notes.md`，明确“只使用这些演示材料，缺失内容标待补”，然后调用对应 Skill。将结果与示例比较时，检查证据、门槛和交付结构，不要求逐字一致。这里没有发布动作，也不需要付费资料。
