# 选题评估

使用 `assets/topic-backlog.template.md` 记录候选题；评分与证据门槛见 `references/scoring-rubric.md`。

## 输入与缺口

- 最少需要：候选题或素材片段、目标读者。用户已提供的信息不重复询问。
- 可选：账号定位、作者相关经验、拟发布时间、可用来源、投入上限。
- 缺少最少输入时，集中询问影响判断的信息；可先列选题角度，但不代填读者或编造完整评分。
- 缺少证据时，可做暂定评估，将受影响的分数写为“待补”，说明要补什么才可改判。

## 工作流

1. 写清选题的一句话判断、目标读者和触发它的真实场景。
2. 找出文章必须回答的一个问题，以及结论依赖的关键事实；给来源编号，分别记录来源核对动作与主张判定。
3. 按规则分别评估好奇心、信息增量、情绪共鸣、作者资格和时效风险，各写分数及一句依据。
4. 对时效事实记录核验时间、版本或有效期。能查到来源不代表风险低；临近截止的官方活动仍属高风险。
5. 给出“现在写 / 补材料后写 / 暂缓”，说明决定性理由、最先补的材料与改判条件。

评分辅助比较，不相加决定去留；时效风险越高越容易过时，其余维度越高越有利。
没有一手经历也可写可靠资料整理；不得把公开资料包装成作者亲测。
来源核对动作仅为“未读取 / 已读取”，已读取不等于已证实。主张判定使用参考规则中的七态；纯主观建议单列“不适用（主观判断）”。

## 交付物

- 每个候选一张选题卡，包含核心问题、可提供的增量、五维评分及依据。
- 证据清单：编号、支持的事实、来源定位、来源核对动作、主张判定、核验时间与适用范围。
- 明确结论及下一步；多候选时说明优先顺序与资源取舍。

## 验收

- 分数有具体依据，未知项显式留缺口，不把热度当作价值。
- “现在写”的关键事实为“已证实”，或在写清适用条件后为“有条件成立”；已证伪、冲突、过时主张不得作为确定依据。
- 能说明为什么值得写、何时会过时、什么新证据会改变结论。
