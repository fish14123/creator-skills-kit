# 长文结构

先填 `assets/article-brief.template.md`，再按 `references/structure-patterns.md` 选择结构。

## 输入与缺口

- 最少需要：目标读者、主张或待回答的问题、至少一段实质素材；改稿时读取现有正文。
- 可选：篇幅、发布渠道、作者口吻、不得改动的事实与案例、引用来源。
- 缺少最少输入时，集中询问；可提供结构方向，但不编造故事、采访、亲历或文章结论。
- 素材足以构思但关键证据未齐时，输出“暂定大纲”和缺口；缺口用占位标记，不扩写为事实。

## 工作流

1. 用一句话锁定文章主张或待验证问题：读者读完后应改变什么认识。没有足够材料时保留问题，不强行得出结论。
2. 建立材料表：编号、内容、来源位置、来源核对动作、主张判定与适用边界；标记事实 F、案例 E、判断 J、待核 U。
3. 依据材料选结构，解释选择理由；判断型和故事型是可选模式，不强迫素材套模板。
4. 给每一节写一句功能说明，并关联材料编号；检查证据是否直接支持该节主张，案例能否支持外推。
5. 标明依赖关键待核材料的段落及补齐条件；改稿时保留用户指定的事实与案例，必要调整说明理由。

F 表示内容类型，不代表已证实。来源核对动作仅为“未读取 / 已读取”，已读取不等于证实；主张判定使用参考规则中的七态，纯主观建议单列“不适用（主观判断）”。

## 交付物

- 文章地图：读者起点 → 核心问题/主张 → 支撑材料 → 读者可采取的行动或边界。
- 大纲：每节功能、要表达的判断、材料编号和证据缺口；按需要展开到三级，不为凑层级增加标题。
- 开头和结尾各 2 个方向；涉及缺失场景时写构思说明，不捏造叙事细节。
- 最先补的材料清单及完成条件；若关键证据未齐，明确大纲是暂定版。

## 验收

- 各节推进问题而非重复结论，每节材料能定位来源；删除空转段落。
- 不用单个案例证明普遍因果，不把不同时间或条件的材料拼成同一经历。
- 待核内容、个人判断与已证实事实可区分；已证伪、与来源冲突、已过时主张不得作为大纲确定依据，应纠正、收窄或删除。
