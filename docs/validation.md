# 验证说明

本项目把验证分为三层。记录结果时写明执行日期、仓库提交、工具或模型以及能否联网，不能把其中一层的通过当成其他层已通过。

本轮已执行与未执行的项目见[2026-11-06 验证记录](validation-report.md)。

## 1. 静态检查

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/validate.py
```

脚本检查 Skill 名称与目录、必要元数据、重复 YAML 字段、引用资源是否存在、简单行内链接的文件目标以及 CSV 表头和列数。链接检查支持仓库目前使用的 `[名称](相对路径)` 形式；不覆盖引用式链接、带标题链接或目标中含空格的链接。只使用本地文件；不验证外部链接是否可访问、Markdown 锚点、事实真伪或模型行为。模板允许只有表头。

[GitHub Actions 配置样例](ci-workflow.example.yml)使用同一检查命令。本版本仅把配置作为文档提供，尚未启用远端 CI。维护者如需启用，可在具有相应权限的环境中将样例复制为 `.github/workflows/validate.yml`，提交后再确认实际运行结果。使用验证脚本只需开发依赖，使用 Skill 本身不需要 Python。

## 2. 助手行为验证

将相关 Skill、引用规则和模板提供给独立助手，再给下面的输入；不要把验收要点一起放入助手提示词。检查实际输出，记录失败项与限制。可在不同模型重复执行；单次通过不代表普遍效果。

全部输入为合成测试素材，无需外部发布或访问会员内容。用例文件：[behavior-cases.md](../evals/behavior-cases.md)。正常任务的输出形态可参考[完整演示](../examples/README.md)，演示由人工整理，不充当独立测评结果。

| 用例 | 主要检查 |
| --- | --- |
| TOPIC-01 | 已核实的短期限免仍有高时效风险 |
| TITLE-01 | 缺正文时，标题准确性与总分待核 |
| STRUCTURE-01 | 无证据素材只形成暂定大纲，缺口不扩写为事实 |
| FACT-01 | 有直接反证时纠正或删除，不能用个人观察保留 |
| FACT-02 | 无联网不能声称核验了今天的价格 |
| REVIEW-01 | 不把 24 小时与 30 天累计量直接排名 |
| DISTRIBUTION-01 | 缺目标平台先补充，不擅自发布 |

## 3. 客户端验证

用[安装指南](installation.md)在指定客户端安装一个 Skill，记录客户端版本、操作系统、安装目录、能否发现并显式调用、能否读取关联文件，再运行相关行为用例。完成发现和读取测试后，仍需独立记录任务结果。

当前仓库只声明目录规范与文档依据，不声明已完成 Claude Code、Codex 或 Cursor 的客户端全流程验收。欢迎贡献验证记录，但不得把一次成功扩展成所有版本兼容。
